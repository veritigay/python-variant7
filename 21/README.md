# Лабораторная работа №21 — вариант 7

**Тема:** итоговый проект: разработка, тестирование и развёртывание прикладной Python-системы.
**Задание:** фитнес-клуб.

## Что делает программа

Законченная система фитнес-клуба на FastAPI + Pydantic + Repository/Service.
Реализованы CRUD клиентов, запись на тренировки, статистика, три бизнес-правила
(проверка действительности абонемента, проверка существования тренера, запрет
двух занятий одного клиента в один день), обработка ошибок с HTTP-кодами,
health check и автоматические pytest-тесты бизнес-правил.

## Эндпоинты

| Метод | Endpoint | Назначение |
|---|---|---|
| GET | `/health` | проверка состояния |
| POST | `/clients` | создание клиента (201) |
| GET | `/clients` | список с фильтрацией |
| GET | `/clients/{id}` | один клиент |
| PUT | `/clients/{id}` | полное изменение |
| DELETE | `/clients/{id}` | удаление (204) |
| POST | `/trainings` | запись на тренировку |
| GET | `/clients/{id}/trainings` | тренировки клиента |
| GET | `/statistics` | статистика |

## Запуск

```bash
pip install fastapi uvicorn pydantic pytest
uvicorn main:app --reload
```

Тесты бизнес-правил:

```bash
python -m pytest -v
```

## Структура

- `main.py` — схемы Pydantic, сущности, Repository, Service, endpoints, тесты.

## Бизнес-правила

- клиент с истёкшим абонементом не может записаться на занятие (409);
- тренер должен существовать (404);
- у клиента не может быть двух занятий в один день (409).

## Проверки

- валидация входных данных через Pydantic (диапазоны, формат даты);
- корректные HTTP-коды (201, 204, 404, 409, 422);
- бизнес-логика отделена от HTTP-обработчиков и покрыта тестами.
